# 网站管理说明

更新：2026-10-14。本说明对应当前公开测试版。

## 免费服务运维实操路线

目前使用 GitHub Pages（网页）、Cloudflare Workers（接口）、D1（数据库），先不购买域名或服务器。页面能打开、接口能连接、登录成功、数据保存是四个不同的检查点。

### 第一课：发布与业务验收

1. 本地 `npm run check` 与生产构建通过后，备份数据库并恢复到临时数据库，检查完整性。
2. 先迁移数据库，再发布 Worker，最后推送前台触发 Pages；认证格式变化不能只发前台。
3. 两个独立账户分别注册、签到、预测，检查余额与订单隔离；新会话登录后再次确认数据。
4. 退款并停用验收账户，保留审计流水。手机 Edge 再实际操作一次；电脑或海外检查点正常，不代表手机线路正常。

2026-10-14 发布使用 `mobile-cold-v2-20261014` 健康标识。生产结构增加 `0007_cold_odds.sql`；`0006` 管理后台仍未发布。不要把“迁移编号有间隔”误认为需要把开发中的迁移也补到生产。

### 第二课：数据库与备份

数据库表分工：`users` 是账户，`password_credentials` 保存密码散列，`sessions` 是可撤销登录状态，`wallets` 是余额，`ledger` 是追加流水，`predictions` 是预测，`game_plays` 是游戏记录。不要只改余额来修订单，必须保持业务记录和流水一致。

本次上线前已导出私有 SQL 备份，并在内存 SQLite 恢复，完整性为 `ok`、外键错误为 0。备份存放在被 Git 忽略的 `backups/`，不能上传到公开仓库或 Actions 日志。现在已完成一次备份恢复演练，尚未配置定期离机备份；本地电脑上的备份不能代替离机备份。后续课程再配置独立保管位置和恢复演练频率。

### 第三课：日志与健康检查

- Cloudflare → Workers & Pages → `night-city-api` → Observability 查看请求与错误。服务端错误记录请求 ID、方法、状态及错误码，不记录请求正文、密码、会话令牌、恢复码或原始数据库错误。
- [Website health check](https://github.com/Not1u/night-city-predictions/actions/workflows/health.yml) 在前台发布结束后执行，也可手动运行；每小时第 17、47 分钟执行一次，只读取公开数据。
- 检查网页及主脚本、API、D1 查询、公开赔率和 CORS；失败时 Actions 显示红色记录。GitHub 自带失败通知取决于个人 Actions 通知设置，尚未配置短信、邮件服务或即时告警渠道。
- 本地可运行 `node scripts/check-live.mjs` 做同样检查。这不是持续注册压测，不自动创建账户，也不代表完整业务验收通过。
- GitHub 定时任务可能延迟，公开仓库长期不活动还可能暂停。后台日志也有额度和保留期限；不要将这些免费检查理解为全天候服务保证或永久审计存储。

官方说明：[Workers Logs](https://developers.cloudflare.com/workers/observability/logs/workers-logs/)、[GitHub 定时工作流](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)。

### 第四课：故障定位与回退

网页不加载先看 Pages 发布记录；网页可见但“检测连接”失败，检查设备网络、DNS 与接口域名；接口可达但注册失败，看状态码和请求 ID 对应的后台日志。不要把所有问题都归因于密码或浏览器。

前台通过还原出问题的 Git 提交后重新发布回退；Worker 通过 Cloudflare 部署历史选择上一版本，或重新部署已验证源码。数据库新字段这次是兼容增加项，旧后端可以保留字段运行，不要为回退网页而删字段或覆盖生产数据库。数据恢复会覆盖上线后的新记录，必须先停写、另存当前数据并核对恢复范围，不能直接拿旧备份覆盖。

下一轮练习：手机 Edge 实测与错误定位、查看一次线上日志、手动运行健康检查、配置私有离机备份，再完善管理员权限与运营后台。这些尚未完成的项目不会被标为已上线。

## 目前有哪些管理入口

独立管理后台目前只有框架，尚未实现管理员登录、二次验证、正式开封盘及结算操作；不存在可直接使用的默认管理员账号。不要把本地管理页当成已上线的运营后台。

日常内容通过 GitHub 更新，新用户名密码账户、服务和数据库由 Cloudflare 管理（旧邮箱认证数据仍保留在 Appwrite）。它们使用站长的平台账号，普通访客没有这些权限。

## 修改公告和开播日期

打开 [公告数据文件](https://github.com/Not1u/night-city-predictions/blob/main/apps/web/src/content/announcements.json)，登录 GitHub 后点铅笔编辑。

1. `lastReviewed`：这次实际核对官方原文的日期，例如 `2026-10-14`。
2. `schedule.date`：官方当前公布的日期，格式 `YYYY-MM-DD`；未知时改为空字符串，页面显示“待官方确认”。
3. `schedule.note`：补充时间、地区差异或延期说明；`sourceUrl` 指向支持该日期的官方原文。
4. `items`：公告列表，每条包含标题 `title`、用自己的话写的短摘要 `summary`、来源 `source`、原文地址 `url`、原文发布日期 `publishedAt`。官网入口没有单篇发布日期时填 `null`。
5. 保存修改并提交到 `main`，在 [发布记录](https://github.com/Not1u/night-city-predictions/actions) 等待绿色成功，再刷新网站。

保留 JSON 的引号、逗号和括号。当前来源仅允许 HTTPS 官方域名：cyberpunk.net、cdprojekt.com、cdprojektred.com（代码中列出的 www / press 子域名）及 www.netflix.com。新增来源需先调整校验名单。构建失败不会替换上一个成功版本。

公告现在是人工核对维护，不是自动抓取，也不会自行跟踪延期。只写上线日期等简短事实并链接原文；不搬运完整新闻、剧照、配乐或剧情。原文也可能含预告及剧透，页面已有提示。

**公告日期仅用于展示，不会改变任何轮次，不会自动开放预测、封盘或结算。**

## 测试场和正式开播安排

目前 `beta-sandbox` 是可退款的预测测试场，正式 `episode-01` 仍未开盘。测试场有自己的截止时间，不依赖公告日期；延期前应分别检查公告和测试场截止时间。

Cloudflare 控制台 → Workers & Pages → `night-city-api` 查看后端状态；Storage & Databases → D1 → `night-city-production` 查看数据。`rounds` 表的 `opens_at`、`closes_at` 为 UTC 时间（北京时间减 8 小时）。可在控制台只读查询：

```sql
SELECT id, title, status, is_test, opens_at, closes_at FROM rounds;
```

正式运营前仍需完成：站长身份与二次验证、开封盘控制、结果复核、幂等结算、审计与恢复验证。当前不要通过手改余额、订单、彩池或结算记录来模拟中奖；这些数据彼此有关联。需要延长测试、退款或调整轮次时，应做带条件检查和审计的维护变更。还没有可交给非技术管理员的一键正式结算功能。

## 账户和昵称

当前 GitHub 联机版通过用户名和密码注册，不要求邮箱。每人独立账户，D1 保存散列密码、恢复码散列、钱包、订单和游戏记录；只返回本人记录。密码至少 12 位，使用带随机盐的 scrypt（N=16384、r=8、p=5）。同一运行实例最多两次密码计算，其余最多八个请求短暂排队。

GitHub 与后台跨站部署，使用随机 256 位令牌作为 12 小时会话，服务器仅存令牌散列，浏览器仅在当前标签页 sessionStorage 中保存会话令牌，不保存密码或恢复码。刷新保留登录；新设备或关闭标签页后重新登录，数据仍在服务器。注销撤销当前会话；改密或恢复会轮换恢复码并撤销旧会话。每账户最多五个有效会话，注册单来源每天最多 12 次，登录有来源及账户限速。上线后不再依赖 Appwrite 请求。

用户点击头像修改用户名，之后使用新名字登录。名字唯一且忽略大小写。站长可在 D1 查看 `users`，将确需停用的用户 `disabled` 设为 1 后，该账户及已有会话均不可用；不要直接删除带流水的账户，也不要手动改余额。密码和恢复码都遗失时，不能只凭昵称找回。

旧邮箱账户和余额仍保留，不能用同名注册抢占。当前 Worker 版没有开放自助旧账户迁移；需核实归属后另行维护。朋友可使用新用户名参加测试。独立服务器版的一次性迁移工具说明在下方。

## 准备中的独立服务器密码版（尚未切换线上）

已有用户名密码注册、登录、恢复码找回、修改密码、注销和旧账户一次性迁移入口。前端和后端将同域部署，登录不再调用 Appwrite 或 workers.dev。现有 GitHub Pages 已使用上文的 Worker 用户名密码版；独立服务器方案用于后续更换网络与同域部署。新增版本尚未运行于购买的服务器，不能将本地通过测试等同于国内线路已验证。

本地预览（Node.js 24）：

```powershell
npm run build:server
$env:PUBLIC_ORIGIN='http://127.0.0.1:8788'
$env:DATABASE_PATH='.data/night-city-preview.sqlite'
npm run start:server
```

打开 http://127.0.0.1:8788 。`build:server` 的同域 Cookie 版本只能部署在独立 Node 服务，不可直接上传 GitHub Pages。线上 `build:pages` 使用 `VITE_AUTH_MODE=password-worker` 和跨站令牌登录。

- 密码至少 12 位，使用带随机盐的 scrypt，最多同时进行两次散列计算。数据库不保存原密码；会话和恢复码只保存散列。
- HTTPS 会话为 HttpOnly / Secure / SameSite=Lax Cookie。退出会在服务端撤销；改密或恢复会撤销其他会话、轮换恢复码。
- 恢复码只显示一次。不绑定邮箱，密码和恢复码同时遗失时不能仅凭用户名找回。
- 登录按来源及用户名限速，单 IP 每日最多 5 次注册尝试。共享出口的访客也可能触及限制；后续按实际使用调整。
- 用户名忽略大小写并归一化，改名后使用新用户名登录。旧用户名仍被原账户占用，不能重复注册抢走积分。
- `users.disabled=1` 会阻止密码登录及已有会话访问；此操作目前仍是服务器维护操作，尚无管理网页按钮。
- `/admin` 不开放：此轮完成登录与服务器运行基础，没有宣称已完成开封盘、正式结算或站长管理界面。

### 小服务器部署边界

建议先购买香港、至少 1 GiB 内存、带公网 IPv4 的 Linux 轻量服务器一个月。先核对线路和实际价格，再付款；不选默认的北京年付，也不预付五个月。域名首年报价与续费价分开看，关闭自动续费。不需要额外购买数据库、邮箱服务或控制面板。

仓库 `deploy/` 提供 Caddy HTTPS 配置、systemd 服务和环境变量样板。部署使用 Node.js 24、Caddy 2.10+；在本地构建前端后传到 `/opt/night-city`，通过 `npm ci` 安装锁定依赖。运行身份是无管理员权限的 `nightcity`，数据目录为 `/var/lib/night-city`，配置文件 `/etc/night-city.env` 只允许服务账户读取。Caddy 的 `SITE_DOMAIN` 填实际域名。模板中的 Node 路径按服务器实际安装位置核对。

只开放公网 80/443；SSH 用密钥并限制来源，不开放 8788 或数据库端口。Node 只监听 127.0.0.1。`TRUST_PROXY=1` 只能配合本机 Caddy 使用，由代理覆盖 `X-Real-IP`，不能直接信任访客传入的地址头。Caddy 自动申请证书，需要域名正确解析且 80/443 可达。

静态文件仅从 `apps/web/dist` 读取，数据库、源码、配置和备份放在它之外。不把数据库导出上传到公开 GitHub。每日做私有离机备份并实际恢复一次；SQLite 使用 WAL，应使用 SQLite backup API 或停服务后完整备份，不能只复制正在写入的单个数据库文件。安全更新及备份是后续运营工作，小服务器不能保证抵御大流量攻击。

### 旧数据迁移与旧账号换证

正式切换前停止旧接口写入，私下导出 D1 并导入一个独立的新数据库，核对用户数、钱包、流水、预测及游戏记录。保留每位用户的原 ID，不能用新注册账户替代。现有迁移器适用于新库；已经导入 0001–0004 的数据库，需要核对旧库迁移历史，再在 `local_migrations(name)` 中标记实际已应用文件，随后应用 0005，禁止直接重跑种子 SQL。正式导入与回退演练尚未执行，必须在切流前完成。

旧邮箱账户没有密码。站长先通过原系统的有效已登录会话或其他充分证明核实账户归属，再在新服务器运行：

```sh
npm run account:claim -- 原用户ID --owner-verified
```

这会生成 30 分钟有效的一次性迁移码，只向已核实的账户本人私下提供。本人在“旧账户迁移”输入原用户名、迁移码并设置密码，原余额和订单保持不变。该命令不能重置已经设置密码的账户，也没有公开领取迁移码的接口。不能仅凭提交的昵称或邮箱生成并发放迁移码。

用户现在只需准备云平台登录与域名选择；数据库导入、身份核实和正式切换由部署环节完成，不要求用户自行编辑数据库。
