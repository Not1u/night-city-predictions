# 死人大乐透

在线地址：[死人大乐透](https://not1u.github.io/night-city-predictions/)。前台由 GitHub Pages 发布，Cloudflare Workers + D1 保存历史账户与积分。

## 冷门赔率与移动端连接（2026-10-14）

- 新增 `cold-v2`：命中角色按封盘押注额的倒数分配彩池，再在各角色内按用户投入比例分配。例：总池 200，两个命中角色分别押了 90 和 10，另有 100 押错；两角色分得 20 和 180，冷门每点返还 18。总返还仍为 200。仅一个角色被押中时分走全部彩池；无人押中全退。
- 页面显示“所有有押注角色都命中”的多人参考，无人押注显示“待首注”；输入金额时同时显示投入后的多人参考与单角色命中参考。热门命中也可能不足本金，不把参考数值当作固定返还。
- `0007_cold_odds.sql` 为轮次保存规则版本：草稿和开放测试场启用新规则，已开放的正式轮次保留旧规则；封盘快照固定规则。正式结算实现位于独立服务器版本，线上 Worker 测试场仍仅支持预测与退款。
- Worker 注册、登录与恢复使用严格校验来源的简单跨域请求，省去额外预检往返；改密仍携带授权令牌。其他接口的 JSON 校验不变。请求超时覆盖响应正文，兼容没有 `AbortSignal.timeout` 的浏览器；登录页提供中文诊断、连接检测与注册超时后的登录提示。写请求不会自动重试。
- 发布需要先更新数据库结构、再发布后端，最后发布前台；新前台的 `text/plain` 认证请求需要新后端支持。本次生产仅应用 `0007`，未启用管理后台。后续部署须单独核对尚在开发中的 `0006`，不能把本地迁移目录全量直接应用到生产。
- 若手机仍无法连接 `workers.dev`，上述代码不能保证修复线路。可将已验证可达的自有 API 域名配置为 GitHub 仓库变量 `API_BASE_URL` 并重新构建；目标必须连接同一后端与数据库，不应指向公共中转。自有域名与原入口都需在目标手机实际验证，健康检查成功也不代表注册已经成功。

## 当前多人联机测试（2026-10-14）

直接打开上面的在线地址（不要带 `?demo=1`），每位参与者用独立用户名和至少 12 位密码注册，无需邮箱。注册后保存一次性恢复码，再签到领取 50 积分。账户、余额、预测和游戏记录保存在同一套 D1 数据库中，各用户只能查询自己的私有记录；大家参与同一个测试彩池，公开赔率每 10 秒同步，也可手动刷新。刷新页面或换设备重新登录后数据保留。

倒计时只显示最大的时间单位，例如“约 2 天”“约 3 小时”“约 20 分钟”，最后一分钟不显示秒数。测试预测可随时退款，正式剧集仍未开盘。四个线上验收账户已验证独立余额、共同赔率、订单隔离与重新登录；验收订单均已退款，验收账户已停用。

`?demo=1` 仅为保留的离线演示，不属于联机测试；其数据不迁移为线上积分。GitHub Pages 和 workers.dev 在部分国内网络仍可能连接不稳定；移除邮件依赖不等于改善服务器线路。

先邀请四五位朋友注册独立账户，分别预测不同角色，观察其他设备的彩池和赔率更新，并检查重新登录后的余额、游戏记录与退款。收集设备、浏览器和具体错误，不收集密码或恢复码。服务器和域名购买暂停，完整管理台及正式剧集结算不在此次公开测试范围。

## 启动

需要 Node.js 22.13+（建议 24 LTS）、npm。首次安装需要网络；本地开发不需要 Cloudflare 账户。

```powershell
npm install
npm run dev
```

打开终端显示的本地地址，默认 http://127.0.0.1:5173 。点击“进入演示账户”，确认 18+ 后签到领取 50 €$，即可模拟预测、查看本集订单、积分流水。演示没有结算按钮，不伪装已经接通正式支付。

## 视觉改版（2026-10-13）

按用户指定的中文官网调整为全屏动画首屏、黄色实心/描边标题、切角按钮、红色角色档案与滚动入场。10 张官方角色立绘与封面已保存到本地素材目录；背景视频使用官网 CDN。点击角色立绘可展开档案，原有模拟操作保持可用。

手机、节省流量模式与系统减少动态效果默认不自动加载视频；用户可用首屏开关播放/暂停动效。视频不可用时保留本地封面。素材来源见 [素材记录](docs/architecture/asset-sources.md)。官方素材不属于项目原创，也不表示官方合作或背书。

如默认端口被本机系统占用或拒绝，可运行 `npm run dev -- --port 5180`。浏览器模拟数据按访问地址隔离，不同端口的演示钱包不会自动共享。

另开终端启动 API / 管理端：

```powershell
npm run db:migrate
npm run dev:api
# 另一个终端
npm run dev:admin
```

API 默认 http://127.0.0.1:8787 ，管理员框架默认 http://127.0.0.1:5174 。本地迁移只创建资料与未开盘首轮，不赠送积分、不创建默认管理员。Wrangler 配置中的全零数据库 ID 是占位符，部署前必须替换。

## 切换数据源

在 `apps/web/.env.local` 写入下列内容，重启前台。此模式读取真实本地 D1，但写入功能保持关闭：

```dotenv
VITE_DATA_MODE=api
VITE_API_BASE_URL=http://127.0.0.1:8787
```

默认 `VITE_DATA_MODE=mock`。模拟状态使用 localStorage 的 `night-city-demo-v1`；清除此项即可重置。模拟账户、请求键不支持跨设备同步或跨标签并发保证。正式版必须以服务端为准。

## 验证与构建

### GitHub Pages 演示站

仓库包含 GitHub Pages 自动发布配置。仓库的 Settings → Pages → Source 设为 **GitHub Actions** 后，每次推送 `main` 都会检查代码、运行测试并发布前台。也可以在 Actions 手动运行发布。

本地运行 `npm run build:pages` 可生成相同的发布文件，输出在 `apps/web/dist`。图片和脚本使用相对路径，支持 GitHub 仓库子路径以及后续绑定独立域名。发布内容仅包含前台演示；管理端、数据库和 Worker 不会部署到 Pages。

线上账户与签到已经连接独立后端；本地默认 `mock` 仍是浏览器内演示。GitHub Pages 仅发布前台，不承载数据库。邮箱验证码服务使用 Appwrite 免费方案，实际发送与登录受平台额度和限流约束。

### 本地检查

```powershell
npm run check
npm run build
npm run build:api
```

测试覆盖数据库约束、会话与角色权限、只读接口、模拟签到/请求重试/余额检查/轮次隔离。**这些不等于正式并发资金结算测试通过**，真实资金服务未实现。
